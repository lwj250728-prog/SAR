**报告编号**：TR-2026-08-19-V3.0
**关键词**：大语言模型、认知架构、在线学习、置信度校准、效用空间聚类、分布外检测（OOD）、前提分化、自我认知、自动积累

## 1. 引言与问题演化

### 1.1 从 V2.0 到 V3.0

V2.0 确立了核心架构：效用驱动的 SAR 记忆、双环路（热环在线推理 + 冷环离线重构）、五层校准、临时工作区。V3.0 回答 V2.0 遗留的三个问题，全部通过**真实部署验证**：

1. **同一行动、不同前提（新手 vs 资深），SAR 的策略会不同吗？**——V2.0 的聚类轴与归属轴都是结果效用，情境从不反馈，前提差异被并簇。V3.0 让重构锚定"情境-策略配对的重现模式"，前提分化**随经验累积自动涌现**，无需任何硬编码字段。
2. **SAR 知道 SAR 里有什么吗？**——V2.0 检索是盲扫，模型不知道记忆库的覆盖与置信。V3.0 增加 taxonomyContext（结构层自我认知）与元经验通道（检索失败自动 sar 化）。
3. **经验怎么自动积累？**——V2.0 沉淀依赖模型自觉调用工具。V3.0 增加自动沉淀：turn/end 触发 → 确定性预过滤 → LLM 路由判断 → 直写入库。

### 1.2 核心假设的实证检验

| V2.0 假设 | V3.0 实证结果 |
| :--- | :--- |
| 首次构建应对比 baseRate 基线并按 15% 门槛验收 | **不可达**：2-3 条验证切片上限仅 -6.98% → 双区间验收（冷启动 Δerr ≤ 0，迭代 Δerr ≤ -15%） |
| LLM 因果锚定能稳定产出通过校验的簇 | **随机性显著**：单次抽样可能返回 0 簇/全坏簇/5 个好簇 → 有界重试（reconstructRetries=2） |
| 模板调用（500-4096 token）能拿到 JSON | **曾被思维链静默饿死**：deepseek-v4-flash 默认思考模式吃光预算，输出 `finish: max-tokens` 零文本 → 显式 `reasoningEffort: off` |
| 聚类按结果效用即可 | **不足**：前提（行动者水平/环境约束）不在聚类轴 → 情境-策略配对锚定 |

## 2. 系统顶层架构（V3.0）

```
输入(新经验) → 热环路(在线推理)
    ├── taxonomyContext(检索咨询分类) → covered/gap/no-taxonomy + 路由余量
    ├── 低置信度/高OOD → 临时工作区(Scratchpad)
    ├── 熟路 → 五层校准(含元经验标记) → 预测
    └── 路由余量<0.1 → 自动合成 meta 经验(检索失败sar化)
轮次结束(turn/end) → 自动沉淀(预过滤 → LLM门模板5) → 经验库
经验库 → 采样触发 → 冷环路(离线重构)
冷环路 → 情境-策略锚定(前提分化) → 证据校验 → 双区间验收 → 分类体系
分类体系 → System Prompt(认知摘要) + taxonomyContext(检索咨询)
meta 经验 → 冷环训练切片 → 检索失败模式簇
```

## 3. 核心模块详细设计

### 3.1 前提分化：情境-策略配对锚定（V3.0 关键）

**动机**：同一行动（如"打包推送到 GitHub"）在新手前提与资深前提下，最佳策略不同（教学 vs 直推）。V2.0 的结果效用聚类把它们并簇。

**机制**：
- 重构提示词任务框架：从"按结果效用相似性聚类"改为"按**情境-策略配对的重现模式**聚类"——同一行动在不同前提下策略不同则拆簇；情境措辞差异但策略相同则合并；宁缺毋滥。
- 证据相干性硬约束保持（三维效用接近、两两距离 ≤0.85、≥3 真实证据）——每子簇内部相干即可通过，分化不被校验阻止。
- **≥3 证据下限 = 自然分化阈值**：模式在训练切片内累积够实例才自成簇（实测：训练集中每前提 2 条不拆、4+3 条稳定拆出）。

**实证**（51 条经验，13 条新手/资深打包推送实例）：
- taxonomy v4 验收（Δerr = -25%），长出两个前提分化簇：
  - 簇8（新手教学）：`if 用户是初学者且任务涉及git初始化、远程推送或发布流程 then 先讲解原理并演示完整命令，附上检查清单`
  - 簇9（资深直推）：`if 用户非新手且任务为常规提交推送 then 跳过讲解直接使用最短命令完成`
- 建议层分化生效：新手查询 →"用简单示例先练手，分步操作"；资深查询 →"先验证权限和网络，再快速推送"。

**情境质心由证据推导**：`situationCentroid` 由簇的证据经验（模型选定的模式核心）计算，而非全部结果相似成员——结果向量相同的前提分化簇若按结果归属会互抢全部成员、把质心稀释成混合物，分化会在检索层死掉。

### 3.2 检索咨询分类体系（结构层自我认知）

```
taxonomyContext(情境):
  对每个簇的情境质心(任意极性)计算余弦
  best < coverageThreshold(0.3) → coverage: 'gap'    (SAR 无相关经验)
  无簇                            → coverage: 'no-taxonomy'
  命中                            → coverage: 'covered'
                                    + 路由余量 = best - 次佳
                                    余量 < retrievalFailureMargin(0.1) → 建议文本标注"路由置信低"
```

**实证**：
- 新手打包查询：`covered, similarity=0.602, margin=0.050` → 建议行显式标注"路由置信低"——系统主动暴露自己的误路由（新手情境被路由到资深簇）。
- 陌生查询（写诗）：`gap, similarity=0.216 < 0.3` → "SAR 无相关经验"，明确走全新现象分支。
- 首次重建前：`no-taxonomy`。
- **已知局限**：环境故障查询余弦 0.291，恰好低于 0.3 → 误判缺口；前提判别 token 在 384 维哈希词袋里被共享任务词稀释（新手情境对簇8 0.552、对簇9 0.602）——确定性路由可能选错前提簇，LLM 校准层路由正确。

### 3.3 检索失败自动 sar 化（元经验通道）

```
熟路预测 + 路由余量 < 0.1 + 无相似 meta 经验(行动余弦≥0.8去重)
  → 自动合成 meta 经验:
      situation = 检索路由歧义：情境「X」与簇「Y」的余弦余量仅 0.050，确定性路由置信低
      action    = 原始查询行动(使其可被未来查询检索到)
      outcome   = 同样行动的路由余量低于0.1，确定性路由不可靠，应改用LLM路由
      utility   = (3,4,5)
  → meta=true，进冷环训练切片
```

**实证**：新手打包/新手发布两次预测自动合成 exp_56/exp_57；模拟重构形成相干 `[exp_55, exp_56, exp_57]` 风险簇（maxDist 0.699 ≤ 0.85 PASS）。

### 3.4 自动积累（模板5：记忆评估门）

```
turn/end(completed/error)
  → 从会话日志重建片段(情境=用户请求, 行动=工具调用序列, 结果=结束原因)
  → 确定性预过滤: 纯聊天(无工具调用+无失败+短输出) → 跳过
  → LLM 门(模板5): 判断是否值得沉淀 + 提取SAR + 三维效用, 参考top-3历史相似经验
  → 值得 → 直写入库(普通verified经验) / 不值得 → 丢弃
```

**设计要点**：
- 成本守卫：纯聊天轮次不进 LLM 门。
- 判断标准（宁缺毋滥）：成功经验（完成有价值工作）与失败经验（踩坑、定位根因）都值得；与历史高度重复的不值得。
- 无 LLM 路由时门确定性拒绝——自动积累永不无判断运行。

### 3.5 双区间验收（V3.0 关键）

**动机**：V2.0 要求首次构建对照 baseRate 基线且 Δerr ≤ -15%。真实数据证明这在 2-3 条验证切片上不可达（实测上限 -6.98%），冷启动永远过不了门。

**机制**：
```
firstBuild = (无已存簇)
referenceError = oldError ?? baseRate误差(空视图)
accepted = firstBuild ? Δerr ≤ 0 : Δerr ≤ -0.15
```
- 冷启动区间：首次验证过的簇集合只要**不劣于**纯 baseRate 猜测即验收（证据硬约束已把关簇质量）。
- 迭代区间：保持 15% 门槛，重建必须显著改善。

**实证**：v1（冷启动，Δerr=-42%）、v2（迭代，Δerr=-50%）、v4（迭代，Δerr=-25%）连续验收；v3 因前提实例不足被诚实拒绝（最新留出切片低 gain 未被训练簇很好预测，属设计中的累积动态）。

### 3.6 模板调用 reasoningEffort: off（V3.0 修复）

**根因**：deepseek-v4-flash 默认思考模式把 4096 maxTokens 预算全部消耗在推理上，输出零文本、以 `max-tokens` 终止 → 每次重构调用抛 LLM_MAX_TOKENS → 静默降级到确定性回退，改进后的提示词从未到达模型。

**修复**：`callJson` 为全部四个模板调用（SAR/OOD/校准/重构）+ 积累门显式设置 `reasoningEffort: ReasoningEffortId('off')`。这是预算受限的 JSON 提取任务的正确选择；主代理循环保留自己的 provider 默认。

## 5. 非功能性需求与成本估算（V3.0 更新）

### 5.1 延迟
- 热环路：检索（当前 N=57 实测 0.047ms/查询；十万级线性扫描实测 212.8ms → 需倒排索引）+ LLM 推理。
- 冷环路：有界重试使单次重建最多 3 次重构调用。

### 5.2 Token 消耗
- 模板调用统一 reasoningEffort off 后，单次模板调用 token 消耗显著下降（思维链不再占用预算）。
- 自动积累：每实质轮次 1 次 LLM 门调用（纯聊天被预过滤）。

### 5.3 存储
- experiences 表增补 simulated/verification/evidence_score/meta 字段，单条记录增加约 100 字节。

## 6. 实验验证方法论

### 6.1 真实数据验证（替代 V2.0 的合成基准）
- 用其他会话的真实对话内容提取经验（非合成），验证冷环在真实效用分布下的行为。
- **发现**：合成测试（每族效用向量完全相同）掩盖了三个真实阻塞——首次构建门槛不可达、回退绕过证据校验、模板调用被思维链饿死。真实数据验证是必要的。

### 6.2 前提分化实验
- 向 store 累积新手教学/资深直推打包推送实例（不同前提、策略不同）。
- **观测**：训练切片内每前提 ≥3 实例后，LLM 稳定拆出两个前提分化簇；<3 时并入既有簇。

### 6.3 检索建议实验
- 三类查询：前提清晰（新手/资深）、陌生（写诗）、临界（环境故障 0.291）。
- **观测**：covered+低置信标注、gap+无经验声明、临界误判暴露阈值校准问题。

## 7. 异常处理与容灾机制

V2.0 保持，增补：
1. **LLM 抽样随机性**：重构产出无验证簇时按 reconstructRetries 有界重试；确定性回退仍是最终安全网（必须通过同一证据闸门）。
2. **自动积累失败**：turn/end 监听器内 accumulateTurn 异常被捕获记录，不影响会话。
3. **meta 经验膨胀**：行动余弦 ≥0.8 去重 + 冷环采样 TTL 衰减。

---

## 8. 结论与下一步

V3.0 通过真实部署验证了 V2.0 架构的三项关键演进：前提分化随累积自动涌现（taxonomy v4 长出新手教学/资深直推簇）、检索咨询分类体系（taxonomyContext 让低置信路由可见）、经验自动积累（LLM 路由判断更新条件，实测自动合成 meta 经验）。

**下一步方向**：
1. **检索提速**：倒排索引 + top-K 部分选择，十万级检索从 212.8ms 降至亚毫秒。
2. **准确度度量**：Recall@K / 命中率指标进 inspect_memory，把"保证准确度"变成可回归验证。
3. **真实嵌入**：占位哈希词袋（all-MiniLM-L6-v2 stand-in）换真实嵌入，解决前提判别 token 稀释问题。
4. **coverageThreshold 校准**：0.291 vs 0.3 临界案例的数据驱动调优。
5. **触发学习**："是否注入/是否更新"本身成为可学习经验（认知编排插件的元学习延伸）。
